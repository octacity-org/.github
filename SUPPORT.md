# Support

Octacity is an open-source community, not a commercial support provider.

We aim to respond and help as quickly as reasonably possible, but we do not provide guaranteed response times, service-level agreements, or continuous user support.

Before asking for help, review the affected repository's README, documentation, contribution guidelines, existing issues, and discussions. Individual repositories may define their own support process, which takes precedence over this document.

## Bug Reports

Report bugs through the issue tracker of the affected repository.

Before opening a new issue:

- Check whether the problem has already been reported
- Confirm that you are using a supported version or branch
- Follow the repository's issue template
- Include clear reproduction steps
- Describe the expected and actual behavior
- Add relevant logs, screenshots, environment details, or error messages

Do not report credible security vulnerabilities through a public issue.

## Feature Requests and Improvement Ideas

Use the affected repository's public channels.

As a general rule:

- Use **GitHub Discussions** when proposing a new feature, capability, or broader direction
- Use **GitHub Issues** when improving, optimizing, correcting, or extending existing behavior

A repository may define a different process depending on its workflow.

Significant or architectural proposals should be discussed before implementation.

## Implementation Questions

Questions about ongoing work should remain attached to that work.

Use the relevant:

- Issue
- Pull request
- Discussion
- Project thread

Keeping questions in context makes decisions visible to contributors, reviewers, and future maintainers.

## General Octacity Questions

General questions about Octacity may be asked through the organization's GitHub Discussions.

Before creating a new discussion, check whether the question has already been answered in:

- The organization profile
- Shared community files
- Existing discussions
- Relevant repository documentation

## Membership Questions

The [`octacity-org/membership`](https://github.com/octacity-org/membership) repository is used for membership applications, not general membership support issues.

Read its README to understand:

- What membership means
- How the application process works
- How applications are reviewed
- What applicants should expect

If you still have questions and intend to apply, submit a membership application. Questions relevant to your situation can be discussed during the review or interview process if your application progresses.

Do not open separate membership-question issues.

## Security

Credible vulnerabilities should be reported privately through GitHub Private Vulnerability Reporting in the affected repository.

Ordinary security improvements, hardening suggestions, dependency updates, and defense-in-depth changes may be discussed publicly when they do not reveal an exploitable weakness.

See the Octacity [Security Policy](SECURITY.md) for details.

## Private Contact

Do not privately contact individual team leaders, maintainers, or the founder for routine support.

This is especially discouraged for people outside the organization.

Octacity uses GitHub for nearly all project and community activity so that:

- Questions remain visible
- Decisions are documented
- Other contributors can help
- Information is not lost in private messages
- People do not bypass established processes

Private communication should be used only when the relevant policy or reviewer explicitly directs you to it, such as for an interview, conduct report, or sensitive security matter.

## Response Expectations

Octacity is maintained by community members contributing according to their availability.

We do our best to respond promptly, but response times may vary depending on:

- Maintainer availability
- Project activity
- Technical complexity
- The quality and completeness of the request
- Whether the correct support channel was used

Repeated messages, duplicate issues, or private contact will not accelerate a response.

## Where to Ask

Use the following route:

- **Bug:** affected repository's issue tracker
- **New feature or broader proposal:** affected repository's Discussions
- **Improvement or optimization:** affected repository's issue tracker
- **Implementation question:** relevant issue, pull request, or discussion
- **General Octacity question:** organization Discussions
- **Membership:** read the membership repository and apply if appropriate
- **Security vulnerability:** GitHub Private Vulnerability Reporting
- **Ordinary security improvement:** affected repository's public issue tracker
